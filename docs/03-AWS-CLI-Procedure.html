§0 読み方・実行の約束

実行した物と、整えた物

ただし、実行記録のコマンドは ID を直書きしていたので、本書では変数に入れて次へ渡す形に直した。引用符の付け方も PowerShell 向けに付け直した。この整えた形では再実行していない（確認済みなのは、元のコマンドの結果）。 - §2-5〜§2-7は、実行記録に結果だけが残っていて、コマンド原文の記録は無い。確かめた物には「構文確認済み（未実行）」と付けた（AWS には何も実行していない）。 - §5 の削除コマンドは、まだ実行していない（未実行）。実施は 06 の条件。

§2 構築

§2-1 VPC、サブネット、IGW、ルート表

cls; Get-Date
# --- VPC-A ---
$VpcA = aws ec2 create-vpc --cidr-block 10.10.0.0/16 `
  --tag-specifications "ResourceType=vpc,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-vpc-a}]" `
  --query Vpc.VpcId --output text @Aws
# 既定のルート表・NACL・SG に Project タグを付ける（タグ付きの親が無いと、後のサブネット作成が権限で拒否された）
$RtbA0 = aws ec2 describe-route-tables --filters "Name=vpc-id,Values=$VpcA" 'Name=association.main,Values=true' --query 'RouteTables[0].RouteTableId' --output text @Aws
$AclA0 = aws ec2 describe-network-acls --filters "Name=vpc-id,Values=$VpcA" --query 'NetworkAcls[0].NetworkAclId' --output text @Aws
$SgA0  = aws ec2 describe-security-groups --filters "Name=vpc-id,Values=$VpcA" --query 'SecurityGroups[0].GroupId' --output text @Aws
aws ec2 create-tags --resources $RtbA0 $AclA0 $SgA0 --tags 'Key=Project,Value=b3c-500-poc' 'Key=Name,Value=b3c-500-poc-vpc-a-default' @Aws
# --- サブネット（A 公開・A 非公開）---
$SnPub = aws ec2 create-subnet --vpc-id $VpcA --cidr-block 10.10.0.0/24 --availability-zone $Az `
  --tag-specifications "ResourceType=subnet,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-subnet-a-public}]" `
  --query Subnet.SubnetId --output text @Aws
$SnPrvA = aws ec2 create-subnet --vpc-id $VpcA --cidr-block 10.10.1.0/24 --availability-zone $Az `
  --tag-specifications "ResourceType=subnet,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-subnet-a-private}]" `
  --query Subnet.SubnetId --output text @Aws
# --- IGW（VPC-A だけ）---
$Igw = aws ec2 create-internet-gateway `
  --tag-specifications "ResourceType=internet-gateway,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-igw-a}]" `
  --query InternetGateway.InternetGatewayId --output text @Aws
aws ec2 attach-internet-gateway --internet-gateway-id $Igw --vpc-id $VpcA @Aws
# --- ルート表（A 公開・A 非公開）---
$RtbPub = aws ec2 create-route-table --vpc-id $VpcA `
  --tag-specifications "ResourceType=route-table,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-rtb-a-public}]" `
  --query RouteTable.RouteTableId --output text @Aws
$RtbPrvA = aws ec2 create-route-table --vpc-id $VpcA `
  --tag-specifications "ResourceType=route-table,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-rtb-a-private}]" `
  --query RouteTable.RouteTableId --output text @Aws
aws ec2 create-route --route-table-id $RtbPub --destination-cidr-block 0.0.0.0/0 --gateway-id $Igw @Aws
aws ec2 associate-route-table --route-table-id $RtbPub --subnet-id $SnPub --query AssociationId --output text @Aws
aws ec2 associate-route-table --route-table-id $RtbPrvA --subnet-id $SnPrvA --query AssociationId --output text @Aws
# --- VPC-B ---
$VpcB = aws ec2 create-vpc --cidr-block 10.20.0.0/16 `
  --tag-specifications "ResourceType=vpc,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-vpc-b}]" `
  --query Vpc.VpcId --output text @Aws
$RtbB0 = aws ec2 describe-route-tables --filters "Name=vpc-id,Values=$VpcB" 'Name=association.main,Values=true' --query 'RouteTables[0].RouteTableId' --output text @Aws
$AclB0 = aws ec2 describe-network-acls --filters "Name=vpc-id,Values=$VpcB" --query 'NetworkAcls[0].NetworkAclId' --output text @Aws
$SgB0  = aws ec2 describe-security-groups --filters "Name=vpc-id,Values=$VpcB" --query 'SecurityGroups[0].GroupId' --output text @Aws
aws ec2 create-tags --resources $RtbB0 $AclB0 $SgB0 --tags 'Key=Project,Value=b3c-500-poc' 'Key=Name,Value=b3c-500-poc-vpc-b-default' @Aws
$SnPrvB = aws ec2 create-subnet --vpc-id $VpcB --cidr-block 10.20.1.0/24 --availability-zone $Az `
  --tag-specifications "ResourceType=subnet,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-subnet-b-private}]" `
  --query Subnet.SubnetId --output text @Aws
$RtbPrvB = aws ec2 create-route-table --vpc-id $VpcB `
  --tag-specifications "ResourceType=route-table,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-rtb-b-private}]" `
  --query RouteTable.RouteTableId --output text @Aws
aws ec2 associate-route-table --route-table-id $RtbPrvB --subnet-id $SnPrvB --query AssociationId --output text @Aws
Get-Date; cb
  • 目的：両 VPC、サブネット 3 つ、IGW（VPC-A のみ）、ルート表を作り、ID を変数 $VpcA、$VpcB、$SnPub、$SnPrvA、$SnPrvB、$Igw、$RtbPub、$RtbPrvA、$RtbPrvB に入れる。
  • 確認方法：§3 の確認コマンドで、VPC 2・サブネット 3・IGW 1・ルート表（既定 2 を含む）5 がすべてタグ付きで出る（実測：確認済み）。
  • 注意点1：作成と同時にタグを付ける（--tag-specifications）。識別タグが無いと、IAM の許可（Project タグ付きだけ）に当たらず拒否される。
  • 注意点2：最初の試行では、タグ付き VPC の中の CreateSubnet が拒否された（UnauthorizedOperation）。ポリシーを v3 に直して通った（実行記録）。再現しない場合は問題なし。
  • 注意点3：VPC-B には IGW を付けない。VPC-A の IGW は 1 つだけ。

§2-2 セキュリティグループ

cls; Get-Date
function New-PocSg($name, $desc, $vpc) {
  aws ec2 create-security-group --group-name $name --description $desc --vpc-id $vpc `
    --tag-specifications "ResourceType=security-group,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-$name}]" `
    --query GroupId --output text @Aws
}
$SgWan  = New-PocSg 'vrx-wan' 'vRX WAN SSH admin and IPsec' $VpcA
$SgLan  = New-PocSg 'vrx-lan' 'vRX LAN from PoC CIDRs' $VpcA
$SgEiceA = New-PocSg 'eice-a' 'EIC Endpoint A' $VpcA
$SgEc2A = New-PocSg 'ec2a' 'EC2-A' $VpcA
$SgEiceB = New-PocSg 'eice-b' 'EIC Endpoint B' $VpcB
$SgEc2B = New-PocSg 'ec2b' 'EC2-B' $VpcB
# vrx-wan：22/tcp は管理者 /32 のみ（500/4500 の UDP は §2-5 で VPN 作成後に外側 IP の /32 だけ許可する）
aws ec2 authorize-security-group-ingress --group-id $SgWan --ip-permissions "IpProtocol=tcp,FromPort=22,ToPort=22,IpRanges=[{CidrIp=$AdminIp/32,Description=admin-ssh}]" --query Return --output text @Aws
# vrx-lan：全プロトコルを両 VPC の CIDR から
aws ec2 authorize-security-group-ingress --group-id $SgLan --ip-permissions 'IpProtocol=-1,IpRanges=[{CidrIp=10.10.0.0/16},{CidrIp=10.20.0.0/16}]' --query Return --output text @Aws
# ec2a / ec2b：ICMP を 10.0.0.0/8、22/tcp を EIC Endpoint の SG から
aws ec2 authorize-security-group-ingress --group-id $SgEc2A --ip-permissions 'IpProtocol=icmp,FromPort=-1,ToPort=-1,IpRanges=[{CidrIp=10.0.0.0/8}]' --query Return --output text @Aws
aws ec2 authorize-security-group-ingress --group-id $SgEc2A --ip-permissions "IpProtocol=tcp,FromPort=22,ToPort=22,UserIdGroupPairs=[{GroupId=$SgEiceA}]" --query Return --output text @Aws
aws ec2 authorize-security-group-ingress --group-id $SgEc2B --ip-permissions 'IpProtocol=icmp,FromPort=-1,ToPort=-1,IpRanges=[{CidrIp=10.0.0.0/8}]' --query Return --output text @Aws
aws ec2 authorize-security-group-ingress --group-id $SgEc2B --ip-permissions "IpProtocol=tcp,FromPort=22,ToPort=22,UserIdGroupPairs=[{GroupId=$SgEiceB}]" --query Return --output text @Aws
Get-Date; cb
  • 目的：6 つの SG と規則を作る。確認方法：各コマンドが True。§3 で規則を一覧する。
  • 注意点：実際の構築では、最初に vrx-wan の 500/udp・4500/udp を 0.0.0.0/0 で一時的に開け、VPN 作成後に絞った。本書の順序は、最初から開けない形に直した（未再実行）。

§2-3 キーペアと EC2

cls; Get-Date
# キーペア（秘密鍵は画面に出さずファイルへ。<AWS_CRED_DIR> は git の対象外）
aws ec2 create-key-pair --key-name b3c-500-poc-key --key-type rsa --key-format pem `
  --tag-specifications "ResourceType=key-pair,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-key}]" `
  --query KeyMaterial --output text @Aws | Set-Content -LiteralPath (Join-Path $poc 'b3c-500-poc-key.pem') -Encoding ascii
# vRX（t3.medium、ENI 2 本。DeviceIndex 0=LAN1 公開側、1=LAN2 非公開側）
$Vrx = aws ec2 run-instances --image-id $VrxAmi --instance-type t3.medium --key-name b3c-500-poc-key `
  --network-interfaces "DeviceIndex=0,SubnetId=$SnPub,PrivateIpAddress=10.10.0.10,Groups=$SgWan,AssociatePublicIpAddress=false" `
                       "DeviceIndex=1,SubnetId=$SnPrvA,PrivateIpAddress=10.10.1.5,Groups=$SgLan" `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-vrx}]" `
                       "ResourceType=volume,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-vrx}]" `
                       "ResourceType=network-interface,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-vrx}]" `
  --query 'Instances[0].InstanceId' --output text @Aws
$Eni = aws ec2 describe-network-interfaces --filters "Name=attachment.instance-id,Values=$Vrx" `
  --query 'NetworkInterfaces[].[Attachment.DeviceIndex,NetworkInterfaceId]' --output text @Aws
$Eni0 = ($Eni -split "`n" | Where-Object { $_ -match '^0\s' }) -replace '^0\s+',''
$Eni1 = ($Eni -split "`n" | Where-Object { $_ -match '^1\s' }) -replace '^1\s+',''
# EC2-A / EC2-B（t3.micro。公開 IP なし）
$Ec2A = aws ec2 run-instances --image-id $LinuxAmi --instance-type t3.micro --key-name b3c-500-poc-key `
  --network-interfaces "DeviceIndex=0,SubnetId=$SnPrvA,PrivateIpAddress=10.10.1.10,Groups=$SgEc2A,AssociatePublicIpAddress=false" `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-ec2-a}]" `
                       "ResourceType=volume,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-ec2-a}]" `
                       "ResourceType=network-interface,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-ec2-a}]" `
  --query 'Instances[0].InstanceId' --output text @Aws
$Ec2B = aws ec2 run-instances --image-id $LinuxAmi --instance-type t3.micro --key-name b3c-500-poc-key `
  --network-interfaces "DeviceIndex=0,SubnetId=$SnPrvB,PrivateIpAddress=10.20.1.10,Groups=$SgEc2B,AssociatePublicIpAddress=false" `
  --tag-specifications "ResourceType=instance,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-ec2-b}]" `
                       "ResourceType=volume,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-ec2-b}]" `
                       "ResourceType=network-interface,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-ec2-b}]" `
  --query 'Instances[0].InstanceId' --output text @Aws
aws ec2 wait instance-running --instance-ids $Vrx $Ec2A $Ec2B @Aws
Get-Date; cb
  • 目的：vRX 1 台（t3.medium・ENI 2 本）と EC2-A・EC2-B（t3.micro）を起動し、ID を $Vrx、$Eni0、$Eni1、$Ec2A、$Ec2B に入れる。
  • 確認方法：wait instance-running が戻る。§3 で 3 台が running、ENI0 が 10.10.0.10、ENI1 が 10.10.1.5。
  • 注意点1：AssociatePublicIpAddress=false を指定する（公開 IP を自動で付けない）。vRX の公開側は次の EIP で付ける。
  • 注意点2：インスタンス・ボリューム・ENI の 3 種類にタグを付ける。ENI を別の種類として指定しないと、ENI にタグが付かない。
  • 注意点3：vRX の AMI は Marketplace の購読が前提。購読が無いと OptInRequired 系のエラーになる（予想。今回は購読済みで起動できた）。

§2-4 EIP、送信元／送信先チェック、ルート、EIC Endpoint

cls; Get-Date
# EIP を確保して、vRX の ENI0（LAN1・公開側）に関連付け
$Eip = aws ec2 allocate-address --domain vpc `
  --tag-specifications "ResourceType=elastic-ip,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-vrx-eip}]" `
  --query AllocationId --output text @Aws
aws ec2 associate-address --allocation-id $Eip --network-interface-id $Eni0 --query AssociationId --output text @Aws
$VrxEip = aws ec2 describe-addresses --allocation-ids $Eip --query 'Addresses[0].PublicIp' --output text @Aws   # 値は画面に出さない
# 送信元／送信先チェックを無効化（ENI 2 本とも）
aws ec2 modify-network-interface-attribute --network-interface-id $Eni0 --no-source-dest-check @Aws
aws ec2 modify-network-interface-attribute --network-interface-id $Eni1 --no-source-dest-check @Aws
# VPC-A 非公開ルート表：VPC-B 宛てを vRX の LAN2 の ENI へ
aws ec2 create-route --route-table-id $RtbPrvA --destination-cidr-block 10.20.0.0/16 --network-interface-id $Eni1 @Aws
# EIC Endpoint（2 本）
$EiceA = aws ec2 create-instance-connect-endpoint --subnet-id $SnPrvA --security-group-ids $SgEiceA --no-preserve-client-ip `
  --tag-specifications "ResourceType=instance-connect-endpoint,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-eice-a}]" `
  --query InstanceConnectEndpoint.InstanceConnectEndpointId --output text @Aws
$EiceB = aws ec2 create-instance-connect-endpoint --subnet-id $SnPrvB --security-group-ids $SgEiceB --no-preserve-client-ip `
  --tag-specifications "ResourceType=instance-connect-endpoint,Tags=[{Key=Project,Value=b3c-500-poc},{Key=Name,Value=b3c-500-poc-eice-b}]" `
  --query InstanceConnectEndpoint.InstanceConnectEndpointId --output text @Aws
# create-complete になるまで待つ（約 5 分）
do { Start-Sleep 30
  $st = aws ec2 describe-instance-connect-endpoints --instance-connect-endpoint-ids $EiceA $EiceB --query 'InstanceConnectEndpoints[].State' --output text @Aws
  Write-Host $st } while ($st -match 'in-progress')
Get-Date; cb
  • 目的：EIP の付与、2 本の ENI の送信元／送信先チェックの無効化、VPC-A から VPC-B への経路、EIC Endpoint の作成。
  • 確認方法：describe-network-interfaces の SourceDestCheck が False・False。EIC Endpoint が create-complete（約 5 分、確認済み）。VPC-A の非公開ルート表に 10.20.0.0/16 → ENI1。
  • 注意点1：送信元／送信先チェックの無効化は、v3 の個別の許可だけでは UnauthorizedOperation で拒否された。管理ポリシー AmazonEC2FullAccess を足して通った（02 の §0-6）。
  • 注意点2：EIC Endpoint の作成は、最初 create-failed（理由：自動で作られる ENI への ec2:CreateTags が許可されない）。失敗した Endpoint は自動で消えないので、delete-instance-connect-endpoint で消してから作り直した。管理ポリシーを足した後の再作成は成功した。
  • 注意点3：EIP は ENI0（公開サブネット側）に付ける。$Eni1 に付けない。$VrxEip の値は画面・ログに出さない。

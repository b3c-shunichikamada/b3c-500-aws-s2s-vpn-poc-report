§4 停止（S6b）の手順と、止めても残る課金

削除ではない。証跡を取る前には止めない。

cls; Get-Date
# 停止（ID は 03 の §3 で取り直す）。EC2 を 3 台とも
aws ec2 stop-instances --instance-ids $Vrx $Ec2A $Ec2B --profile b3c-500-poc --region ap-northeast-1
aws ec2 wait instance-stopped --instance-ids $Vrx $Ec2A $Ec2B --profile b3c-500-poc --region ap-northeast-1
# aws ec2 start-instances --instance-ids $Vrx $Ec2A $Ec2B --profile b3c-500-poc --region ap-northeast-1
Get-Date; cb
止まる課金 止まっても残る課金
EC2 の時間料金（vRX の t3.medium、EC2-A・EC2-B の t3.micro） VPN 接続（0.048 USD/時）：VPN 接続を削除しない限り続く
vRX のソフト代（0.02 USD/時）：インスタンスが停止している間は使用量が発生しないと見込まれる（未確認。Marketplace の請求で確認） Elastic IP（パブリック IPv4）：付けたままでも、外しても、解放するまで課金が続く
EBS のボリューム：停止中も、容量に応じて続く
EIC Endpoint：時間課金の有無は未確認
  • 注意点1：vRX を停止して再開すると、VPN のトンネルは落ち、vRX の IPsec は再接続される（設定が保存されていることが前提。保存の確認は 04）。EIP は変わらない。
  • 注意点2：停止中に VPN 接続を残すのは、停止のたびに外側 IP や PSK が変わらないようにするため。VPN 接続を削除すると、外側 IP と PSK が変わって作り直しになる。
  • 注意点3：停止は AWS の変更操作。

§6 削除手順

証跡の取得が終わるまで削除しない。

§6-1 AWS のリソース

コマンドは 03 の §5（ID 指定・逆順）を使う。順序の要点：VPN 接続 → VGW（VPC から外して削除）→ CGW → EC2 の終了 → EIP の解放 → EIC Endpoint → キーペア → ルート表の関連付け解除と削除 → サブネット → IGW → SG → VPC。

§6-IAM 関係（IAM は利用者を削除する前にキーとポリシーを外す順で行う）

順 対象 操作（IAM コンソール）
1 アクセスキー IAM → ユーザー → b3c-500-poc-cli → セキュリティ認証情報 → アクセスキーを「非アクティブ化」→ 続けて「削除」
2 利用者からのポリシーの取り外し IAM → ユーザー → b3c-500-poc-cli → 許可 → b3c-500-poc-policy を「削除」（取り外し）
2b 管理ポリシー 2 つの取り外し（追加） 同じ「許可」タブで AmazonEC2FullAccess と EC2InstanceConnect を「削除」（取り外し）。AWS の管理ポリシーなので、ポリシー自体は削除せず取り外すだけ
3 ポリシーの削除 IAM → ポリシー → b3c-500-poc-policy → 削除
4 利用者の削除 IAM → ユーザー → b3c-500-poc-cli → 削除
5 ローカルのフォルダ <AWS_CRED_DIR>\ フォルダを削除（認証情報ファイルが入っている）
6 git の除外設定 <GIT_EXCLUDE_FILE> から <AWS_CRED_DIR>\ の行を削除
  • 注意点1：IAM の操作は、b3c-500-poc-cli ではできない（その利用者に IAM の操作権限は無い）。
  • 注意点2：手順 5 の前に、AWS の残存確認（§7）をすべて終える。<AWS_CRED_DIR>\ を消すと、CLI で確認できなくなる。
  • 注意点3：手順 2 のポリシー名は 02 の §0-3 で作成したカスタマー管理ポリシー（中身は v3）。

§7 残っていないことの確認

AWS のリソースを削除した後、<AWS_CRED_DIR>\ を消す前に、次を実行する。すべて 0 件（または期待の値）になること。

cls; Get-Date
$env:AWS_SHARED_CREDENTIALS_FILE = '<AWS_CRED_DIR>\credentials'
$env:AWS_CONFIG_FILE = '<AWS_CRED_DIR>\config'
$Aws = @('--profile','b3c-500-poc','--region','ap-northeast-1')
$f = 'Name=tag:Project,Values=b3c-500-poc'
'VPC';      aws ec2 describe-vpcs --filters $f --query 'Vpcs[].VpcId' --output text @Aws
'Subnet';   aws ec2 describe-subnets --filters $f --query 'Subnets[].SubnetId' --output text @Aws
'IGW';      aws ec2 describe-internet-gateways --filters $f --query 'InternetGateways[].InternetGatewayId' --output text @Aws
'RouteTbl'; aws ec2 describe-route-tables --filters $f --query 'RouteTables[].RouteTableId' --output text @Aws
'SG';       aws ec2 describe-security-groups --filters $f --query 'SecurityGroups[].GroupId' --output text @Aws
'NACL';     aws ec2 describe-network-acls --filters $f --query 'NetworkAcls[].NetworkAclId' --output text @Aws
'Instance'; aws ec2 describe-instances --filters $f 'Name=instance-state-name,Values=pending,running,stopping,stopped,shutting-down' --query 'Reservations[].Instances[].InstanceId' --output text @Aws
'ENI';      aws ec2 describe-network-interfaces --filters $f --query 'NetworkInterfaces[].NetworkInterfaceId' --output text @Aws
'Volume';   aws ec2 describe-volumes --filters $f --query 'Volumes[].VolumeId' --output text @Aws
'EIP';      aws ec2 describe-addresses --filters $f --query 'Addresses[].AllocationId' --output text @Aws
'EIC';      aws ec2 describe-instance-connect-endpoints --filters $f --query 'InstanceConnectEndpoints[?State!=`delete-complete`].InstanceConnectEndpointId' --output text @Aws
'CGW';      aws ec2 describe-customer-gateways --filters $f --query 'CustomerGateways[?State!=`deleted`].CustomerGatewayId' --output text @Aws
'VGW';      aws ec2 describe-<VPN_ID> --filters $f --query 'VpnGateways[?State!=`deleted`].VpnGatewayId' --output text @Aws
'VPN';      aws ec2 describe-<VPN_ID> --filters $f --query 'VpnConnections[?State!=`deleted`].VpnConnectionId' --output text @Aws
'KeyPair';  aws ec2 describe-key-pairs --filters $f --query 'KeyPairs[].KeyName' --output text @Aws
Get-Date; cb
  • 確認方法：各行の結果が空（0 件）。deleted・delete-complete の状態は、一時的に一覧に残ることがあるため除いてある。
  • 注意点1：EIP と EBS は、タグが付いていない場合がある。EIP は describe-addresses を全件で見て、PoC の ID（<EIP_ALLOC_ID>）が無いことも確認する。EBS は、describe-volumes を全件で見て、状態 available（付け先なし）の物が無いことを確認する。
  • 注意点2：この確認は読む操作だけ。

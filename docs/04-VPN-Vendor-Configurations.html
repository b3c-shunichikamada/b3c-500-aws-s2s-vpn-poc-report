04 VPN メーカー別設定（Cisco・Yamaha・Fortinet）— 内部用

状態: 内部用の資料。社外用は別に作る。PSK と管理者の IP は変数（<PSK>・<ADMIN_IP>）で書き、ほかの IP は実値で書いている。

0. 先に読むこと（何が実機で、何が資料だけか）

メーカー 実機で検証したか 位置づけ
Yamaha vRX（Amazon EC2 版 Rev.20.00.03） はい。この PoC で実際に Tunnel1 を張り、双方向 ping 5/5 を確認した（05 の T02〜T07） 実機に入れた設定をそのまま載せる
Cisco いいえ（実機検証なし） AWS が配る CSRv のサンプルを元に、今回の CIDR・IKEv2・Static に合わせた例
Fortinet いいえ（実機検証なし） AWS が配る FortiOS 6.4.4+ (GUI) のサンプルを元にした設定

このため仕様のうち「T05 Cisco IKE SA」「T06 Cisco IPsec SA」は、実際には vRX の IKE SA・IPsec SA で確認している（05 に明記）。

1. AWS から直に取った物と、PoC 用に直した物（区別）

区別 内容
AWS から直に取った物 設定サンプル 3 本（get-<VPN_ID>-device-sample-configuration、IKEv2 指定）。原本は <AWS_CRED_DIR>\samples\（git 管理外・PSK 入り）、伏せた写しは <WORK_DIR>\samples\ の yamaha_e7a2d626_redacted.txt・cisco_csrv_7b754310_redacted.txt・fortinet_7125681a_redacted.txt
PoC 用に直した物 暗号（AES256・SHA2-256・DH14）、宛先 CIDR（10.20.0.0/16）、外側の口、ポリシー番号など。本書の「PoC での直し」欄と、各設定のコメントに書いた

AWS サンプルの暗号は AWS の最低要件の例（AES128・SHA1・DH2）で、VPN 接続に付けたオプションを反映しない（AWS サンプルのコメントにも「AES256 などに直す必要がある」とある）。今回の VPN の Tunnel1 のオプションは describe で実測した値: IKEv2、Phase1・2 暗号 AES256、整合 SHA2-256、DH14、DPD 再起動、StartupAction=add。

2. AWS から設定を取る方法（Download configuration と CLI）

2-1. Web コンソール

VPC → Site-to-Site VPN connections → 対象の VPN → 「Download configuration」→ Vendor（メーカー）・Platform（機種）・Software（版）・IKE version（IKEv1／IKEv2）を選んでダウンロード。

2-2. CLI（この PoC で使った方法）

aws ec2 get-<VPN_ID>-device-types --profile b3c-500-poc --region ap-northeast-1
aws ec2 get-<VPN_ID>-device-sample-configuration --<VPN_ID>-id <VPN_ID> --<VPN_ID>-device-type-id <ID> --internet-key-exchange-version ikev2 --profile b3c-500-poc --region ap-northeast-1 --query VpnConnectionDeviceSampleConfiguration --output text
aws ec2 describe-<VPN_ID> --<VPN_ID>-ids <VPN_ID> --profile b3c-500-poc --region ap-northeast-1

今回使った device type ID: | メーカー | ID | 一覧での名前 | |---|---|---| | Yamaha | e7a2d626 | RTX（Rev.10.01.16+）。vRX の項目は一覧に無い | | Cisco | 7b754310 | CSRv AMI | | Fortinet | 7125681a | FortiGate 40+ Series（FortiOS 6.4.4+ (GUI)） |

2-3. 公式に無い機種・版（事実）

  • Cisco Catalyst 8000V（C8000V）は AWS の一覧に無い。Cisco は CSRv AMI・ASA・Meraki が載っている（AWS 公式 example-configuration-files、2026-11-01 取得で確認）。本書の Cisco 例は CSRv のサンプルを元にした。
  • Yamaha vRX は一覧に無く、RTX 総称のサンプルのみ。Yamaha 公式にも「AWS の VGW と vRX の設定例」は無い。vRX の設定は RTX サンプルと Yamaha コマンドリファレンスの突き合わせで作り、実機で確認した。
  • Fortinet FortiOS 5.0+（9d9470de）は IKEv2 指定で UnsupportedOperation となり取れなかった（IKEv2 非対応）。IKEv2 で取れた物は FortiOS 6.4.4+ (GUI)（7125681a）。

4. Yamaha vRX（実機に入れた設定）

4-1. 構成

  • vRX（EC2 版 Rev.20.00.03、t3.medium）。LAN1（eth0）が外向き（公開サブネット 10.10.0.0/24、EIP 付き）、LAN2（eth1）が内向き（10.10.1.0/24）。
  • 初期 config の既定経路は lan2。EIP を LAN1 に付けたため、ip route default gateway dhcp lan1 へ変更が必要だった（これをしないと SSH も IPsec の返事も LAN2 へ出てしまう）。
  • EC2 側: 送信元/送信先チェックを両 ENI で無効、VPC-A の非公開サブネットのルート表に 10.20.0.0/16 → vRX の LAN2 の ENI を向ける。

4-2. 入れた設定（実機の show config から。PSK 等は変数）

administrator password *                        ! 設定した（値は書かない）
ip route default gateway dhcp lan1              ! 初期は lan2。EIP が LAN1 にあるため変更
ip route 10.20.0.0/16 gateway tunnel 1
ip lan1 address dhcp                            ! 10.10.0.10/24
ip lan2 address dhcp                            ! 10.10.1.5/24
ipsec use on
tunnel select 1
 ipsec tunnel 201
  ipsec sa policy 201 1 esp aes256-cbc sha256-hmac
  ipsec ike version 1 2
  ipsec ike duration ipsec-sa 1 3600
  ipsec ike duration ike-sa 1 28800
  ipsec ike encryption 1 aes256-cbc
  ipsec ike group 1 modp2048
  ipsec ike hash 1 sha256
  ipsec ike keepalive use 1 on rfc4306 10 3
  ipsec ike local address 1 10.10.0.10
  ipsec ike local name 1 3.115.198.19 ipv4-addr
  ipsec ike nat-traversal 1 on
  ipsec ike pfs 1 on
  ipsec ike proposal-limitation 1 on
  ipsec ike message-id-control 1 on
  ipsec ike child-exchange type 1 2
  ipsec ike pre-shared-key 1 text <PSK>
  ipsec ike remote address 1 13.196.38.153
  ipsec ike remote name 1 13.196.38.153 ipv4-addr
  ipsec ike negotiation receive 1 off
 ipsec tunnel outer df-bit clear
 ip tunnel address 169.254.236.126/30
 ip tunnel remote address 169.254.236.125
 ip tunnel tcp mss limit auto
 tunnel enable 1
ipsec auto refresh on

投入の手順: SSH で入る（ec2-user とキーペア。Rev.20 は初回にパスワード設定）→ administrator（設定変更は管理レベルが必要）→ console lines infinity（ページャが次の入力の 1 文字目を食うのを防ぐ）→ 上のコマンドを入れる → save。

4-3. 確認コマンド（実機で使った物）

show ipsec sa                 ! IKE SA 1 本、ESP の send/recv 各 1 本
show status tunnel 1          ! 「トンネルインタフェースは接続されています」、IKE キープアライブ OK
show ip route                 ! 10.20.0.0/16 が TUNNEL[1] 向き
show config

EC2 側: ping -c 5 10.20.1.10、sudo traceroute -I -n -m 3 10.20.1.10（1 段目が vRX の 10.10.1.5。tracepath は ICMP 時間超過が返らず使えない）。

4-4. 戻し方

管理レベルで tunnel select 1 → tunnel disable 1 → no ipsec tunnel 201 ほか該当コマンドの no 形、no ip route 10.20.0.0/16 gateway tunnel 1、save。または AWS の VPN 接続を削除する。

4-5. AWS の Yamaha サンプル（RTX、e7a2d626）との差

項目 AWS サンプル 実機に入れた物（PoC 用に直した点）
暗号 aes-cbc（AES128）・sha・modp1024（最低要件の例） aes256-cbc・sha256・modp2048。VPN の options に合わせた
IKE 寿命の書式 ipsec ike duration isakmp-sa ike-sa（vRX のコマンドリファレンスの書式）。どちらも受理された
ポリシー番号 ipsec tunnel 201・sa policy 201 同じ 201
DPD keepalive use 1 on rfc4306 10 3 同じ
追加項目（サンプルに有り） message-id-control、child-exchange type 1 2、negotiation receive off、df-bit clear、ipsec auto refresh すべて入れた
NAT-T・提案固定 サンプルは注記のみ nat-traversal on・proposal-limitation on を入れた（EIP は NAT の内側にあるため。実機で確立した）
口と local address サンプルは 1 つの外向き口を想定 local address は LAN1 の私設 IP 10.10.0.10、local name は EIP
経路 キープアライブ付きの例（コメント） ip route 10.20.0.0/16 gateway tunnel 1（キープアライブなし。Tunnel2 を使わないため）

5. Cisco（実機検証なし。AWS の CSRv サンプルを元にした例）

出典: AWS の設定サンプル（device type 7b754310、CSRv AMI、IKEv2 指定）の伏せた写し <WORK_DIR>\samples\cisco_csrv_7b754310_redacted.txt。C8000V は AWS の一覧に無いため CSRv を元にした。IOS XE の C8000V でも同系統のコマンドだが、C8000V・実機では未検証。

5-1. PoC 用に直した点（サンプルとの差）

項目 AWS サンプル PoC 用
IKEv2 提案 aes-cbc-128・sha1・group 2 aes-cbc-256・sha256・group 14
IPsec esp-aes 128 esp-sha-hmac、pfs group2 esp-aes 256 esp-sha256-hmac、pfs group14
宛先経路 ip route 10.0.0.0 255.255.255.0 Tunnel1（サンプルの例示値） ip route 10.20.0.0 255.255.0.0 Tunnel1
トンネル送信元 <interface_name/private_IP_on_outside_interface> 外向き口の私設 IP（この PoC の構成なら 10.10.0.10 相当）。EIP の内側にある場合の identity local は 未確認（AWS サンプルは書いていない）

5-2. 設定例（PSK・IP は変数）

crypto ikev2 proposal PROPOSAL1
  encryption aes-cbc-256
  integrity sha256
  group 14
exit
crypto ikev2 policy POLICY1
  match address local <OUTSIDE_PRIVATE_IP>
  proposal PROPOSAL1
exit
crypto ikev2 keyring KEYRING1
  peer 13.196.38.153
  address 13.196.38.153
  pre-shared-key <PSK>
exit
crypto ikev2 profile IKEV2-PROFILE
  match address local <OUTSIDE_PRIVATE_IP>
  match identity remote address 13.196.38.153
  authentication remote pre-share
  authentication local pre-share
  keyring local KEYRING1
  lifetime 28800
  dpd 10 10 on-demand
exit
crypto ipsec transform-set ipsec-prop-<VPN_ID>-0 esp-aes 256 esp-sha256-hmac
  mode tunnel
exit
crypto ipsec profile ipsec-<VPN_ID>-0
  set pfs group14
  set security-association lifetime seconds 3600
  set transform-set ipsec-prop-<VPN_ID>-0
  set ikev2-profile IKEV2-PROFILE
exit
crypto ipsec df-bit clear
crypto isakmp keepalive 10 10
crypto ipsec security-association replay window-size 128
crypto ipsec fragmentation before-encryption
interface Tunnel1
  ip address 169.254.236.126 255.255.255.252
  ip virtual-reassembly
  tunnel source <OUTSIDE_PRIVATE_IP>
  tunnel destination 13.196.38.153
  tunnel mode ipsec ipv4
  tunnel protection ipsec profile ipsec-<VPN_ID>-0
  ip tcp adjust-mss 1379
  no shutdown
exit
ip route 10.20.0.0 255.255.0.0 Tunnel1

注: AWS サンプルは Tunnel1 の定義の直後に Tunnel2 の分が続く。今回は Tunnel2 を使わないので省いた。

6. Fortinet（実機検証なし。AWS の FortiOS 6.4.4+ (GUI) サンプルを元にした設定）

出典: device type 7125681a（FortiGate 40+ Series、FortiOS 6.4.4+ (GUI)、IKEv2 指定）の伏せた写し <WORK_DIR>\samples\fortinet_7125681a_redacted.txt。FortiOS 5.0+ のサンプル（9d9470de）は IKEv2 指定で UnsupportedOperation（IKEv2 非対応）となり取れなかった。実機では未検証。

6-1. GUI 手順（AWS サンプルのまま。PoC 用に直した点は「PoC」と印を付けた）

  1. VPN → IPsec Tunnels → Create New → Custom。名前は <VPN_ID>-0（15 文字未満の制約あり）。
  2. Network: IPv4、Remote Gateway = Static IP Address = 13.196.38.153、Local Interface = wan1、Local Gateway は WAN 側の IP を指定、DPD = On Idle/On Demand、認証 = Pre-shared Key = <PSK>、IKE Version = 2。
  3. Phase 1 Proposal: 暗号 aes256、認証 sha256、DH 14（サンプルは aes128・sha1・DH2。PoC）、寿命 28800 秒。NAT Traversal は有効のまま（EIP の内側にある場合）。
  4. Phase 2 Selectors: 暗号 aes256・認証 sha256（PoC）、Replay Detection 有効、PFS 有効・DH 14（PoC）、寿命 3600 秒、Auto-negotiate 有効。Local Address = 自側のサブネット（0.0.0.0/0 でも可）、Remote Address = 10.20.0.0/16（PoC）。
  5. トンネルインタフェース: Network → Interface → wan1 の下の <VPN_ID>-0 を編集し、IP = 169.254.236.126、Remote IP = 169.254.236.125/30、Ping を選択、Administrative Status = Up。
  6. 静的経路: Network → Static Routes → Create New、Destination = 10.20.0.0/16（PoC）、Interface = <VPN_ID>-0。
  7. ファイアウォールポリシー: 内側 → トンネル、トンネル → 内側の 2 本（Service = ALL、Action = ACCEPT）。
  8. Link Monitor（CLI のみ、サンプルのまま）: 下の CLI。

6-2. 設定 CLI

サンプルの CLI は MTU/MSS と link-monitor だけで、残りは GUI 手順。次の phase1/phase2 の CLI は、GUI 手順を FortiOS の一般的な CLI 構文に私が書き換えた物で、AWS のサンプルには無く、FortiOS の実機でも未検証。

config vpn ipsec phase1-interface
  edit "<VPN_ID>-0"
    set interface "wan1"
    set ike-version 2
    set remote-gw 13.196.38.153
    set dpd on-idle
    set nattraversal enable
    set proposal aes256-sha256
    set dhgrp 14
    set keylife 28800
    set psksecret <PSK>
  next
end
config vpn ipsec phase2-interface
  edit "<VPN_ID>-0"
    set phase1name "<VPN_ID>-0"
    set proposal aes256-sha256
    set dhgrp 14
    set pfs enable
    set replay enable
    set keylifeseconds 3600
    set auto-negotiate enable
    set dst-subnet 10.20.0.0 255.255.0.0
  next
end
config system interface
  edit "<VPN_ID>-0"
    set ip 169.254.236.126 255.255.255.255
    set remote-ip 169.254.236.125 255.255.255.252
    set allowaccess ping
    set mtu-override enable
    set mtu 1427
    set tcp-mss 1379
  next
end
config router static
  edit 1
    set dst 10.20.0.0 255.255.0.0
    set device "<VPN_ID>-0"
  next
end
config system link-monitor
  edit 1
    set srcintf "<VPN_ID>-0"
    set server "169.254.236.125"
    set interval 2000
    set failtime 5
  next
end

（config system interface の MTU/MSS と link-monitor の値は AWS サンプルのまま。他は上の注のとおり未検証。）

§0-5 CLI プロファイルの登録（PowerShell）

AWS CLI の認証情報ファイルは、既定の場所（利用者フォルダ）ではなく、リポジトリ内の <AWS_CRED_DIR>\ に置く。<AWS_CRED_DIR>\ は <GIT_EXCLUDE_FILE> に足し、git に載らないようにする。

次のコマンドをそのまま実行する。aws configure の入力欄に、アクセスキー ID・シークレット・リージョン ap-northeast-1・出力形式 json を入れる。

cls; Get-Date
$poc = '<AWS_CRED_DIR>'
New-Item -ItemType Directory -Force -Path $poc | Out-Null
$ex = '<GIT_EXCLUDE_FILE>'
if (-not (Select-String -LiteralPath $ex -Pattern '^\<AWS_CRED_DIR>\$' -Quiet)) { Add-Content -LiteralPath $ex -Value '<AWS_CRED_DIR>\' }
$env:AWS_SHARED_CREDENTIALS_FILE = Join-Path $poc 'credentials'
$env:AWS_CONFIG_FILE = Join-Path $poc 'config'
aws configure --profile b3c-500-poc
aws sts get-caller-identity --profile b3c-500-poc
git -C '<WORK_DIR>' status --short --ignored <AWS_CRED_DIR>
Get-Date; cb
項目 内容
入力項目と設定値 プロファイル名＝b3c-500-poc／リージョン＝ap-northeast-1／出力形式＝json
確認方法（確認済み） aws sts get-caller-identity --profile b3c-500-poc の結果が arn:aws:iam::<ACCOUNT_ID>:user/b3c-500-poc-cli
git status --short --ignored <AWS_CRED_DIR> の結果が !! <AWS_CRED_DIR>\（git の対象外）
注意点1 AWS CLI v2.37 の aws configure は、最後に「Configure AWS skills and the AWS MCP server for your AI coding agent(s)?」と「Install 24 default AWS skills?」を聞く。B3C では ~/.claude/skills を配布の手順以外で変えないため、どちらも n と答える
注意点2 aws configure は入力したシークレットを画面にそのまま出す。画面の写しを他人に渡さない
注意点3 環境変数 AWS_SHARED_CREDENTIALS_FILE と AWS_CONFIG_FILE はその PowerShell の窓の中だけで有効。新しい窓では §0-5 の 2 行を再設定してから --profile b3c-500-poc を使う

§0-6 管理ポリシー 2 つの追加（2026-11-01 追加）

構築の途中で、ポリシーを v3（<IAM_POLICY_FILE>）にした上で、AWS の管理ポリシー AmazonEC2FullAccess と EC2InstanceConnect の 2 つを利用者に足した。理由は、v3 の個別の許可では「ENI の属性変更（送信元／送信先チェックの無効化）」と「EC2 Instance Connect Endpoint の作成（自動で作られる ENI へのタグ付け）」が拒否されたため。

項目 内容
操作画面名 ユーザーの「許可」タブ・「許可を追加」
メニュー階層 IAM → ユーザー → b3c-500-poc-cli → 許可を追加 → ポリシーを直接アタッチする
入力項目と設定値 AmazonEC2FullAccess と EC2InstanceConnect にチェック → 「許可を追加」
確認方法 確認済み：追加後に modify-network-interface-attribute --no-source-dest-check（2 本とも成功）と EIC Endpoint の再作成（2 本とも create-complete）が通った
注意点1 AmazonEC2FullAccess は広い許可。v3 の Deny（高額・対象外の EC2 操作、タグの削除、東京以外のリージョン）は引き続き効く。それ以外の「Project タグ付きだけに絞る」仕組みは弱くなったため、操作する時は ID を限定して行う
注意点2 削除の時は、この 2 つも外す（06 の削除手順）
未確認 v4（<IAM_POLICY_FILE>）を実際に適用したかどうかは未確認。本書は「v3 ＋ 管理ポリシー 2 つ」で書いた

§1 から §15 の読み方（Console 操作の手順）

  • 構築は AWS CLI で行った（手順は 03）。本節以降は、同じ結果を AWS マネジメントコンソール（Console）で作る手順を、画面名・メニュー階層・入力値・確認方法・注意点の形で書く。
  • 入力値と作成結果は、CLI の実行記録で確かめた物（確認済み）。Console の画面名・ボタン名・メニュー階層は、AWS 公式の日本語ユーザーガイドと突き合わせた。一致した物は「確認済み：公式文書」と出典 URL を付け、文書に無い物は「未確認」と付けた。実画面での操作確認はしていない。実際に Console で操作する人は、画面が違えば画面側を正とし、本書の「入力値」だけを使う。
  • 利用者 b3c-500-poc-cli は Console にログインできない（§0-1）。Console で行う場合は、同等の権限を持つ別の利用者でログインする。
  • すべての資源に識別タグ Project ＝ b3c-500-poc を付ける。Console の作成画面にタグの欄がある場合は、その場で付ける。名前（Name タグ）は 01 の §5 の表と同じにする。
  • リージョンは画面右上で「アジアパシフィック（東京）ap-northeast-1」を選ぶ（未確認）。
  • 順序は 01 の §1 と同じ（VPC → サブネット → IGW → ルート表 → SG → キーペア → EC2 → EIP → ENI の設定 → EIC Endpoint → CGW → VGW → VPN 接続 → 設定のダウンロード）。
